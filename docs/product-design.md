# Design: Habit — 习惯社交承诺平台
Date: 2026-06-06 | Mode: Product

---

## Problem Statement

大多数人知道自己该做什么，却无法真正开始，或开始后无法持续。
问题不是缺乏信息或动力——而是缺乏**外部约束机制**。
现有产品要么只有惩罚（Beeminder），要么只有记录（Habitica），没有产品将
**金钱承诺 × 社交问责 × 社区生态** 融合为一个完整体验。

---

## 核心洞察

> 让一个人坚持，靠意志力；让一个人在众目睽睽下坚持，靠社会压力；
> 让一个人在有真实代价的情况下坚持，靠损失厌恶。
> 三层叠加，才是真正的行为改变基础设施。

YouTube/Bilibili 上关于自律的内容从不缺少——它制造三分热度，不制造行为改变。
这个产品要做的不是内容，是**让改变真实发生的基础设施**。

---

## 目标用户

**核心用户画像：反复尝试、反复失败的人**

不是第一次尝试改变的人（他们还不愿付出代价）。
是那些已经失败过几次、知道靠自己不够、愿意借助外力的人。

典型场景（来自真实对话）：
> 老板交代的重要任务，总在脑海里延后。被紧急事务替代，最后不了了之。
> 想运动、想读书、想早起——开始了三天，断了。

**地域**：中国、美国、东南亚（越南、泰国、印尼）
**语言**：已支持 EN / ZH / ES / KO / JA / VI / TH

---

## 已验证的前提

1. **核心问题是启动失败 + 持续失败**，不是缺乏动力或信息
2. **金钱机制是护城河，但不是入口** — 冷启动必须靠社交/免费价值
3. **社交是留存核心** — 有社交层的习惯 App 留存率高 39%，完成率高 65%
4. **目标用户是"反复失败的人"** — 他们才愿意为承诺付出代价

---

## 产品三层架构

```
┌─────────────────────────────────────────┐
│  深度层（付费/未来）                      │
│  真实货币充值 · 双人对赌 · 承诺押注合约   │
├─────────────────────────────────────────┤
│  社交层（免费增长）                       │
│  社区动态流 · 群体挑战 · 排行榜 · 圈子   │
├─────────────────────────────────────────┤
│  入口层（免费，单人即有价值）              │
│  习惯追踪 · XP/等级 · H 赚取            │
└─────────────────────────────────────────┘
```

**关键设计原则：每一层单独使用时都有价值。**
- 入口层：没有任何朋友也能用，虚拟货币激励个人坚持
- 社交层：看到别人在行动，比看视频更能激励自己
- 深度层：为已建立习惯的用户提供"把真实代价押进去"的选项

## 货币体系设计（分阶段）

App 内货币单位：**H**（源自 Habit，跨语言通用，视觉上作为品牌符号使用）

> **命名逻辑**：H = Habit。一个字母，不需要翻译，7种语言里完全一致。
> 显示方式：`+10 H`、`2,840 H`。未来可设计定制字形，成为品牌资产。
> 注意：UI 上始终保留空格（`10 H` 而非 `10H`），避免与"小时"产生歧义。

### H 与现有 XP 系统的关系

**H 是 XP 的演进版本，不是两套平行系统。**
当前代码中的 `xp` 字段即为 H 的基础。
- 短期（0期）：H 与 XP 数值等价，UI 上逐步将"XP"替换为"H"
- 中期（1期）：H 可充值，XP 仅用于等级计算（两者解耦）
- 长期（2期）：H 可提现，XP 等级系统保持独立作为荣誉体系

### 0期（当前阶段）— 纯虚拟，无监管风险
```
赚取方式：
  - 每次完成习惯打卡        → +10 H
  - 完美日（全部完成）      → +50 H bonus
  - 连续天数里程碑          → 阶梯奖励（3d +10 · 7d +30 · 14d +50 · 30d +100 · 100d +500）
  - 每日首次打开 App        → +2 H

消耗方式：
  - 编辑已启用的习惯        → -20 H（修改代价）
  - 取消已完成的打卡        → -10 H（反悔惩罚）
  - 强制删除进行中习惯      → -30 H（违约惩罚）
  - 购买高级功能/主题       → 消耗 H
```

### 1期（有一定用户后）— 可充值，不可提现
```
充值渠道：微信支付 / 支付宝 / 信用卡
需要：商户资质、支付接入协议
货币用途扩展：购买"免死金牌"、解锁社交特权、群体挑战押注
```

### 2期（生态成熟后）— 可充值 + 可通过习惯赚取并提现
```
需要：法律结构审查、金融/增值电信资质（视国家而定）
这是真正的"习惯投资"模型——坚持习惯，产生真实回报
```

## 双人对赌功能（深度层，非入口）

**适用场景**：有明确可观察输出的习惯（跑步、读书、创作等）
**验证机制**：社会成本 > 技术验证
- 必须上传一张图或一段文字记录
- 对方可见，可评论，可"质疑"
- 被质疑需二次确认；长期信用记录可见

**不适用场景**：无法留下痕迹的习惯（不刷手机、饮食控制等）
→ 这类习惯只走荣誉系统 + 个人记录，不进入对赌机制

## 已考虑的路线

| 路线 | 核心逻辑 | 排除原因 |
|---|---|---|
| A: 金钱优先 | 承诺合约为核心卖点 | 冷启动无解，合规风险高 |
| B: 社交优先 | Strava for Habits | 差异化弱，变现路径长 |
| **C: 货币骨架 + 分层社交** | 个人→社区→押注 | **选定方向** |

## 开放问题

1. **货币单位叫什么名字？** 需要有含义、易记、全球可用
2. **社区动态流的内容边界是什么？** 纯习惯记录？还是允许图文分享？
3. **冷启动策略**：先做哪个地区/哪个人群？（中国用户 vs 东南亚 vs 英语市场）
4. **"启用习惯"的数量上限**：是否限制同时进行中的习惯数量，避免用户过载？

## 最紧迫的任务（The Assignment）

在写任何一行社交功能代码之前，做这一件事：

> **找 5 个真实的人，让他们用现在的 App 一周。**
> 观察他们在哪一天放弃，为什么放弃。
> 这 5 个人的答案，比任何设计文档都重要。

现有 App 已有足够功能支撑这次测试。
需求验证优先于功能建设。

## What I noticed

你一开始说不清楚需求证据——但你用自己的故事（老板的任务、不了了之）描述了一个真实的、有名字的问题。这比"目标用户是想改变的年轻人"具体一百倍。

你对双人对赌的质疑——"似乎只针对某一类型的习惯"——是产品直觉，不是技术问题。你在保护产品的宽度，这个判断是对的。

你对货币的定位："不是虚拟币，是围绕 App 设立的金钱单位，可以通过坚持习惯赚取"——这一句话把产品从"惩罚工具"变成了"行为投资平台"。这是整个产品最有价值的差异化表述。
