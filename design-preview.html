08 — Motion
5-Tier Motion Library

Spring easing only for reward events — earning H, checking a habit, receiving a badge. Smooth ease-out for transitions and reveals. Linear only for loading spinners.

Micro
150–180ms · ease-out
Hover states · button presses
Standard
200–250ms · ease-out
State transitions · checkbox fill
Reveal
300ms · cubic(.22,1,.36,1)
Banners · dropdowns · progress bar
Spring ★
350–450ms · cubic(.34,1.56,.64,1)
Check-in · badge pop · toast entry · H float
Transition
480ms · cubic(.22,1,.36,1)
Calendar slide · page transitions

★ Spring is the language of reward. Use it only when the user earns something — not for routine interactions.

09 — Anti-patterns
What Not to Do

The product is serious. These patterns undermine trust or visual quality.

✕ Never
Hard-code hex values. Every color goes through a semantic CSS variable. color: #7c6af7 → color: var(--accent)
✓ Always
Use semantic token names. Theme switches work automatically. New themes require only variable overrides.
✕ Never
Use Spring animation for destructive or neutral UI. Spring = reward. Deleting a habit should use Standard ease, not a bouncy spring.
✓ Always
Reserve Spring for positive events: check-in, level up, badge pop, H earned. The animation carries emotional meaning.
✕ Never
Display H as plain text number: 2840. It reads as a score, not value.
✓ Always
Display H with tabular-nums, gold color, and unit: 2,840 H. Numbers that look like money build the right mental model.
✕ Never
Leave empty states as "No habits yet." without context or a primary action. That's developer UI, not product UI.
✓ Always
Every empty state: an icon with warmth, honest context copy, and one primary action. Emptiness is an opportunity.
